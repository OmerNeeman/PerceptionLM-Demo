# Brief — S1: source classifier + inventory

**Dispatch:** subagent (pure I/O over local rasters; no weights, no GPU).
**Proves:** spec **D-1**, **D-2**.
**Depends on:** nothing. Runs independently of S0.

## Goal

Turn two facts that reconnaissance already **measured** into code that
**re-derives them reproducibly**: which rasters are source imagery, and what a
pixel is worth on the ground.

## Why this stage exists

`docs/DATA.md` already knows the answers. It cost two long agent runs and it is
measured fact. This stage does **not** re-survey — it encodes the rule so that
every later stage can classify a raster it has never seen, and so that a
regression is caught rather than silently indexed.

Getting D-1 wrong produces an index that looks completely fine and means
nothing: only 12 of ~232 rasters in that tree are real imagery. Indexing a
binary mask as if it were aerial imagery is the signature failure of this
project.

## The D-1 rule — measured, not heuristic

A raster is **source imagery** iff:

1. it has **>= 3 bands**, AND
2. sampled pixel values show **> 64 distinct levels in each of bands 1-3**.

Every derived raster in this tree has **<= 6 distinct values per band**; every
source raster has **187-256**. The margin between 6 and 187 is enormous, so
the 64 threshold is not delicate — but it must be **measured from pixels**.

**Never classify by filename.** Not as a shortcut, not as a fast path, not as
a pre-filter. Filenames in this tree do not distinguish source from derived,
and a filename fast-path is exactly the bug that produces a plausible,
meaningless index.

Sample rather than read whole rasters — these are up to 6.44 gigapixels. State
your sampling strategy and make it deterministic (fixed seed or a fixed stride
/ window grid). D-4 requires that two runs agree.

## The D-2 rule — the GSD trap

For any **Mercator** CRS, ground distance = projected distance x cos(latitude).

```
leb: EPSG:3857, pixel 0.125002 m, centre lat 33.10707
true_gsd = 0.125002 * cos(radians(33.10707)) = 0.125002 * 0.837651 = 0.10471 m
448 px tile = 448 * 0.10471 = 46.91 TRUE ground metres     (not 56.0)
```

The **UTM** scenes (EPSG:32636, k0 = 0.9996 at eastings 709-710 km) are within
0.04% of unity: **no correction, true GSD is 10.00 cm.** Applying the cosine
correction to a UTM scene is as wrong as omitting it from a Mercator one.

So the correction must be **conditional on the CRS being Mercator**, derived
from the CRS itself, not hardcoded per file and not applied globally.

## Acceptance criteria — test-first, paste RED then GREEN

- **D-1** `test_source_classifier`: over `leb`, exactly the two rasters
  `2022-10-29.tif` and `2025-06-06.tif` qualify. Assert the returned set
  equals exactly that pair. Additionally assert the classifier's decision is
  unchanged when the files are addressed through renamed symlinks (create them
  under `retrieval/index/`, never in the data dir) — this is what proves the
  decision is made on pixels and not on the filename.
- **D-1 (breadth)** `test_source_inventory_matches_manifest`: the classifier
  finds exactly the **8 indexed source scenes** listed in `docs/DATA.md`, with
  the dimensions, band counts and CRS recorded there. Excluded-with-cause
  entries (`sin`, `Teheran`/`iran`, `gaza.tiff`) must be classified correctly
  in their own right: `gaza.tiff` is real 3-band imagery but has **no CRS and
  no geotransform**, so it fails as an *indexable scene* for a different reason
  than a binary mask does. Keep those two rejection reasons distinct in the
  output.
- **D-2** `test_gsd_correction`: `leb` reports **10.47 cm/px +/- 0.01** and a
  448 px tile reports **46.91 m +/- 0.05**. The test must **reject 12.5 cm and
  56.0 m explicitly** — assert they are not returned, so a regression to the
  raw geotransform fails loudly rather than looking plausible.
- **D-2 (UTM)** `test_gsd_no_correction_for_utm`: `X605_Y3388.tif` reports
  **10.00 cm/px** and a 448 px tile **44.8 m**. A cosine correction wrongly
  applied here would give ~8.4 cm and must fail the test.
- **D-3** `test_data_dir_readonly`: every output path the module can produce
  resolves inside `retrieval/index/`; and a recursive listing +
  mtime/size digest of the data tree is identical before and after a full
  inventory run.
- **D-4** `test_inventory_deterministic`: two consecutive inventory runs over
  unchanged inputs produce identical JSON (byte-identical, or identical after
  a documented key ordering).

## Constraints

```bash
env PYTHONNOUSERSITE=1 CUDA_VISIBLE_DEVICES=0 \
    /home/omer/anaconda3/envs/geo/bin/python
```

**Your Bash tool does not persist environment variables between calls.**
Prefix **every** python and pytest invocation inline, every time. This stage
needs no GPU, but `PYTHONNOUSERSITE=1` still matters: without it you get a
different interpreter's packages.

- Open every raster **read-only**. `rasterio.open(path)` defaults to `"r"`;
  never pass `"r+"`, `"w"`, or `"a"` for anything under the data root.
- The data directory is READ-ONLY. No writes, moves, renames, or in-place
  conversion. Ever.
- Structured logging at stage boundaries. No catch-and-silence — a raster that
  fails to open is a logged, reported fact, not a swallowed exception.
- Determinism: fixed seed / fixed stride, recorded in the output.
- Never commit anything under `index/`.

## UX expectations

This stage has no user interface, but its **output is read by humans** when an
index build goes wrong. So:

- The inventory records, per raster: path, band count, per-band distinct-value
  count, dimensions, CRS, projected pixel size, **true ground GSD**, whether
  it is source imagery, whether it is indexable, and **the reason** if not.
- Rejection reasons are specific and distinguishable: `derived_raster`
  (<= 6 distinct values), `too_few_bands`, `no_georeference`,
  `resolution_regime_excluded`, `duplicate_of`. Not a bare boolean, and not one
  generic "excluded".
- The summary line a human reads first states counts per reason, so
  "8 indexable, 230 derived, 1 no-georeference, 2 duplicates" is visible
  without opening the JSON.
