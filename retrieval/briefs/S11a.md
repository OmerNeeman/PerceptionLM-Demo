# Brief — S11a: index the corpus with PE-Core-L14-336

**Dispatch:** subagent. **Proves:** F-1a at two models, F-2, N-2, N-4.
**Blocks:** S11b (the selector). **Long-running:** ~21 min of GPU.

## Goal

Embed the **same 104,374 tiles** with **PE-Core-L14-336** alongside the existing
RemoteCLIP index, so a user can later choose between them and compare.

## The one real design decision — index layout

Today: `index/emb/<aoi>/{manifest.json,vectors.npy}`. That path assumes one
model. Two models need model-scoped storage.

**Requirements, not an implementation:**

- The existing **RemoteCLIP index must not be re-embedded.** It is 104,374
  verified vectors and cost real GPU time. Moving or copying files is fine;
  recomputing them is not.
- `load_index` must resolve **which model's index** it is reading, and the
  manifest must continue to record **exactly one** model id and revision.
- **F-1a's mixed-embedder guard must still fire** — a build that would append
  vectors from a different model or revision raises, naming both. That guard is
  tested; keep those tests passing.
- All **166** existing tests stay green. If a test hardcodes the old path,
  update the test, but say so in your handback — do not silently rewrite
  assertions.

State the layout you chose and why in one short paragraph.

## What to build

Embed all 8 scenes across the 4 AOIs — `X605_Y3388`, `leb`, `gaza`, `AYOSH` —
with **`PE-Core-L14-336`** (1024-d).

- Loader already exists: `embedders.load_embedder("PE-Core-L14-336")`.
  `perception_models` is installed at `/home/omer/perception_models` and
  `import core.vision_encoder.pe` works. **Do not rewrite the loader.**
- **Pooled output only.** PE-Core's patch tokens are 1536-d, never entered the
  contrastive objective, and the published attempt at retrieving on them scored
  **2.5 nDCG@5 against 51.4 for pooling**. Settled twice — see
  `notes.md#research-1`.
- Skip only **100%-nodata** tiles, exactly as the RemoteCLIP build did, so the
  two indexes cover the **identical tile set**. This matters: a side-by-side
  comparison is meaningless if the candidate pools differ. **Assert it** —
  embedded tile ids must match the RemoteCLIP index's set exactly.
- Same `batch_size` (256). N-4's determinism is conditional on it.
- `dtype` from `src/device.py`, never hardcoded.
- **Resumable** (N-2). ~21 minutes is long enough to be interrupted.

## Expected cost — and your canary

S0 measured PE-Core-L14-336 at **84.5 tiles/sec** against RemoteCLIP's 265.
For 104,374 tiles that is **~21 minutes**, ~214 MB at 1024-d fp16.

**Check throughput in the first minute.** If you see ~5 tiles/sec,
`PYTHONNOUSERSITE=1` did not apply on that call and the job is on CPU — it will
take **17 hours** and look like it is working the whole time. Kill it and fix
the invocation.

## Report the comparison

Once both indexes exist, run the **same queries against both** and report
side by side: `tents`, `a car`, `dirt road`, `rubble`, plus the known-absent
control `aircraft carrier`. For each, per scale: top-1 score and the top-5
tile ids.

S0's finding, for context — **do not treat it as a target**: RemoteCLIP got
4/5 genuine vehicle crops at 112 px against PE-Core-L14's 3/5, and PE-Core-L14's
control **outscored its own `car` query** (margin **-0.0157** against
RemoteCLIP's +0.0135). That was measured on **336 calibration crops**. You are
measuring on 104,374 tiles. **If PE Core does better here, that is a real
finding and you should say so** — the earlier sample was small.

Raw scores are **not comparable across models** — different spaces, different
scales. Compare *ranked content*, and the within-model control margin.
